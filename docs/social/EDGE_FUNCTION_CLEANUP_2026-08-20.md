## 3. What the retired functions did — preserved, not erased

This is kept deliberately. The functions existed, they shipped, and the record of them stays.

| Function | What it did |
|---|---|
| `generate-public` | Unauthenticated endpoint that generated a social caption and hashtags for a given topic, platform and tone, calling OpenAI on every request behind a durable per-day rate limiter backed by the `public_generate_daily_usage` table. It was the public, no-signup trial of the multi-tenant social-content product. |
| `generate-content` | The authenticated variant of the same generator. It validated the caller itself with `supabase-js` + `auth.getUser()` rather than relying on gateway JWT verification, which is why its config carried an explicit `verify_jwt` setting. |

Both were part of the product removed in May 2026 (see `docs/internal/TRENDS_REMOVAL_INVENTORY.md`
and `docs/JIFUNZE_MASTER_PLAN.md` §2). Their source is preserved in `_quarantined_functions/` and in
git history.

## 5. A note on the compiled bundle

Before this cleanup, `dist/assets/index-*.js` contained the literal string
`VITE_CONTENT_API_URL:"https://…/functions/v1/generate-content"`.

**That was not a source-code caller.** No file in `src`, `scripts`, `orchestrator`, `render` or
`e2e` has ever referenced `VITE_CONTENT_API_URL`. It appeared because the app reads environment
values dynamically — `(import.meta.env as Record<string, string | undefined>)[key]` in
`src/lib/envCheck.ts`, and similar lookups elsewhere. A dynamic key lookup prevents Vite from
tree-shaking individual variables, so it inlines the **entire** `import.meta.env` object, meaning
every `VITE_*` variable present in `.env.local` at build time ends up in the bundle.

Two consequences worth keeping in mind:

1. Now that the variable is out of `.env.local`, a fresh production build cannot contain it.
   Verified by rebuilding.
2. More generally: **any `VITE_*` variable in `.env.local` is compiled into the public bundle**,
   whether or not any code reads it. That is inherent to `VITE_*` (those variables are public by
   design), but it means `.env.local` should hold nothing that is not intended to be public.

`dist/` is gitignored and untracked, so the stale bundle is not part of the code review. It is
regenerated by the normal production build; nothing in it was hand-edited.
